# DeepSeek Harness两天破10万Star，秘密不在模型

#deepseek #deepseekharness #agent #harness 

一个现在还很难用的 AI 工具，
两天拿下 github 10 万 Star。
它叫 DeepSeek Harness。
开发者到底看中了什么？
关键不在于它现在好不好用，
而在 DeepSeek 把过去藏在 AI 产品背后的那一整层能力，全部拆开了。

先说人话，什么是 Harness。
模型只是大脑。它想真正干活，
还需要工具、记忆、文件权限、沙箱、上下文管理
以及一套决定“下一步该做什么”的 Agent 循环，
这些东西加在一起，才是 Harness。

所以同一个模型，放进不同的 Agent 产品里，表现可能完全不同。
差距不一定出在模型能力，而是有没有一套系统，把它的能力稳定地组织起来。

Claude Code、Codex 走的是产品路线：
厂商把整套 Harness 做好，你在里面接工具、装 Skill，然后直接用。

DeepSeek Harness 走的是另外一条路：
从模型适配器、工具注册、会话日志，到 Agent 循环和界面，
几乎每一层都做成插件。
官方给它的定位就一句话——一切皆插件。

这也是它为什么不叫 DeepSeek Code。
它想做的不是又一个Coding agent，而是一套可以被重新组合的 Agent 底盘。

底下撑着这套系统的，是一个叫 Cordis 的内核。

Cordis 主要解决两个问题。

第一，插件卸载以后，它之前注册的能力和产生的影响，能不能干净地撤销。

第二，一个插件依赖的能力发生变化以后，它能不能重新找到依赖，继续工作。

翻译成人话就是：Agent 干活干到一半，你可以给它换工具、换模型，甚至换掉一部分运行逻辑，而不是每改一个地方，就把整套系统推倒重来。

最有想象力的是它的“创造模式”。

Agent 可以检查自己当前有哪些插件、缺什么能力，再尝试创建一个新插件，挂回正在运行的环境里。
就像工人干到一半发现没有扳手，不是停下来等人送，而是现场造一把，装上以后接着干。
当然，先别急着把 Claude Code 和 Codex 都卸了。

DeepSeek Harness 目前还是开发者预览版，官方也明确提醒会有破坏兼容性的更新。


如果你只是想让 AI 帮你写代码，成熟产品依然更省事。
但如果你想研究 Agent 工作原理、给公司定制一套专属 Agent，或者想亲手替换它的界面、工具和运行规则，这套东西就非常值得看。

想体验的话，装好 Node.js，只需要一行命令：

`npx @deepseek-ai/dsh web`

DeepSeek 这次开源的，不只是一个 Agent，而是“Agent 应该怎么被组装”这件事。

未来 AI 的竞争，也不只是谁的模型跑分更高，而是谁能把模型、工具、权限和流程，组织成一套能稳定干活、还能持续变化的系统。
