# SOURCE_OF_TRUTH

本文件定义 DailyWrite 的权威目录和冲突处理规则。后续 Agent 执行 `/script`、`/title`、`/hook`、`/review` 时，以这里为准。

## 权威目录

- 主索引：`00-内容资产索引/内容主索引.md`
- 创作状态：`00-内容资产索引/创作状态看板.md`
- 检索规则：`00-内容资产索引/检索与写回规则.md`
- 实际发布文案：`03-已发布归档/已发布成品/`
- 可复用素材：`02-素材知识库/`
- 平台数据：`04-数据与复盘/`
- 方法论：`05-方法论沉淀/`
- 来源原文：`06-来源原文库/`

## 三层结构

- Raw sources：`06-来源原文库/`，保存原始资料和历史原稿副本，默认不改写。
- Wiki：`02-素材知识库/` 和 `05-方法论沉淀/`，保存 LLM 编译后的可复用资产。
- Schema：`SOURCE_OF_TRUTH.md`、`AGENTS.md`、`CLAUDE.md`，定义目录职责和工作流。

## 非默认检索目录

以下目录默认不作为创作素材入口，除非用户明确点名：

- `.agents/`
- `.claude/`
- `.obsidian/`
- `.recode/`
- `.trash/`
- `90-工具项目/`
- `tmp/`
- `remotion-wechat-intel-opening/`（迁移前旧路径）
- 任意 `node_modules/`、`out/`、缓存目录

## 冲突规则

1. 实际发布文案以 `03-已发布归档/已发布成品/` 中绑定 `content_id` 的成品文件为准；该目录必须保存正文，不能只有数据文件指针。
2. 播放、完播、收藏、涨粉等平台数据冲突时，以 `04-数据与复盘/抖音数据/00-抖音数据汇总表.md` 和对应单条数据文件为准。
3. 方法论文件中的历史数据如果与平台数据冲突，先更新方法论中的数据基座，再继续引用。
4. 同一选题有多个脚本版本时，以 `内容主索引.md` 标记的当前版本为准。
5. 外层冷备份中的历史过程稿只用于明确的版本追溯，不参与默认素材检索，也不能直接当作最新成品。
6. `06-来源原文库/` 中的文件是原始来源，不直接等同于个人观点或生产方法论。

## 已发布资产同步规则

- 每个公开作品必须同时具备：唯一 `content_id`、实际发布成品、平台数据文件、主索引记录。
- `03-已发布归档/已发布成品/README.md` 是已发布成品总览；`00-内容资产索引/内容主索引.md` 负责连接成品、数据、复盘和可复用资产。
- 当前抖音公开作品通过 `90-工具项目/published-archive-sync/sync-published-archive.mjs` 从显式映射表同步。脚本遇到未映射数据文件、空正文、重复 ID 或断链时必须直接报错。
- 图文原页缺失时必须明确标记“待补”，不得用相近草稿冒充实际发布内容。

## 草稿版本留存规则

- `03-已发布归档/草稿归档/` 已删除，不得重新创建。
- 历史草稿、不同模型稿、低版本、高版本、相关图片和其他过程文件统一移出 DailyWrite，进入知识库外层冷备份。
- 外层冷备份不参与 `/script`、`/title`、`/hook`、`/review` 和默认检索。
- 实际发布内容必须先完整进入 `03-已发布归档/已发布成品/`，再移动对应过程产物。
- 移动后必须保留原路径、目标路径和哈希记录；已发布成品如需溯源，只记录外层冷备份路径，不得重新依赖草稿归档。
- `03-已发布归档/` 只允许保存 `已发布成品/`；不得保存草稿归档、根目录整理、迁移清单、未命名 Canvas/Base 或相关整理中间产物。

## 写回规则

每次完成 `/review` 后必须判断是否写回：

- 新观点、新概念：写入 `02-素材知识库/核心概念库/`
- 可复用表达：写入 `02-素材知识库/金句语录库/`
- 成功或失败案例：写入 `02-素材知识库/爆款拆解库/`
- 稳定结构：写入 `05-方法论沉淀/`

## Ingest / Lint 规则

- `/ingest [来源文件]`：读取 `06-来源原文库/` 中的来源，更新 `SOURCE_REGISTRY.md`，把抽取结果写入 `02-素材知识库/` 或 `05-方法论沉淀/`，并追加 `00-内容资产索引/log.md`。
- `/lint`：按 `00-内容资产索引/lint-checklist.md` 检查索引、来源、素材、方法论、数据复盘之间的冲突和缺口；默认只输出待修复清单，不大规模改写旧内容。
