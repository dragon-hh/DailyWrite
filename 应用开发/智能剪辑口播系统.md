## 一、产品概述

### 1.1 背景

口播视频创作者在内容生产中面临大量重复性剪辑工作：删除卡顿、口误、冗余表达、啰嗦段落。现有工具（剪映等）只能删静音/停顿，无法理解内容质量。本系统通过 AI 对内容语义层面进行分析，主动标记"说得不好的地方"，并提供可视化的人工审核+一键导出流程。

### 1.2 核心价值

- **内容级别的智能删减建议**（区别于剪映的音频级静音检测）
- **人工可控的审核流程**（AI 建议 + 人工最终确认）
- **全流程可视化**（转录→标记→预览→导出，一个界面完成）
- MiniMax 模型驱动分析，作为广告合作的技术案例展示

### 1.3 目标用户

- 口播类内容创作者（知识博主、AI 领域 UP 主）
- 需要批量剪辑素材的视频团队
- AI 工具开发者（参考案例）

## 二、系统架构

### 2.1 技术选型

|层级|技术|说明|
|---|---|---|
|前端|React + Vite|SPA，与后端分离部署|
|后端|Python FastAPI|处理上传、任务调度、FFmpeg 调用|
|转录|MiniMax 语音识别 API|生成带时间戳的字幕|
|AI 分析|MiniMax 文本模型|分析字幕，标记删除片段|
|视频处理|FFmpeg（本地/服务端）|执行剪辑、导出|
|任务队列|本地进程 / 可选 Redis+Celery|异步处理视频任务|
|存储|本地文件系统（MVP）|视频文件、字幕、剪辑结果|
|通信|WebSocket|实时推送任务进度|

### 2.2 部署形态

**MVP 阶段**：本地桌面化部署（用户本机运行 Python 服务 + 浏览器访问），无需云服务器，降低初期成本。

**后续扩展**：Docker 镜像一键部署，支持私有化部署给客户（咨询业务场景）。

### 2.3 整体数据流

```
用户上传视频
    ↓
后端存储原始文件
    ↓
Step 1: 调用 MiniMax ASR → 返回带时间戳字幕（SRT/JSON）
    ↓
Step 2: 调用 MiniMax 文本模型 → 分析字幕，返回"标记删除片段"列表
    ↓
Step 3: 前端渲染审核页（文字稿 + 红色高亮标记）
    ↓
Step 4: 用户手动增删标记
    ↓
Step 5: 用户点击"预览剪辑" → 后端 FFmpeg 生成预览片段 → 前端播放
    ↓
Step 6: 用户点击"导出" → FFmpeg 导出最终视频 → 用户下载
```

### 3.2 模块 1：视频上传与管理

**功能：**

- 支持拖拽上传或点击选择，格式：MP4、MOV、MKV、AVI
- 文件大小限制：MVP 阶段 4GB（本地处理无云存储限制问题）
- 上传后立即显示原始视频播放器（左栏）
- 显示视频基本信息：时长、分辨率、文件大小

**状态机：**

```
idle → uploading → uploaded → transcribing → analyzing → ready_for_review → exporting → done
```

每个状态对应 UI 状态更新，WebSocket 实时推送。

**接口：**

```
POST /api/upload          # 上传视频，返回 task_id
GET  /api/task/{task_id}  # 查询任务状态
WS   /ws/{task_id}        # 实时进度推送
```

---

### 3.3 模块 2：视频转录（Step 1）

**功能：**

- 后端接收到视频后，自动触发转录
- 调用 MiniMax 语音识别 API，获取带时间戳字幕
- 支持语言：中文（主）、中英混合

**MiniMax ASR 调用逻辑：**

- 如视频过长（>15min），后端先用 FFmpeg 切分为若干音频片段，分批调用 API 后合并结果
- 转录结果存储为标准格式：

```json
{
  "segments": [
    {
      "id": 1,
      "start": 0.0,
      "end": 3.2,
      "text": "大家好我是龙视",
      "confidence": 0.98
    },
    ...
  ]
}
```

**错误处理：**

- API 超时：自动重试 3 次，失败后提示用户手动触发
- 转录结果置信度 < 0.7 的片段：UI 中用下划线标注，提示用户核对

---

### 3.4 模块 3：AI 分析（Step 2）

**功能：**

- 转录完成后，将字幕 JSON 提交给 MiniMax 文本模型
- 模型返回"建议删除片段"列表，附带删除理由

**Prompt 设计（系统提示词）：**

```
你是一个专业的口播视频剪辑顾问。你的任务是分析视频字幕，找出应该删除的片段。

删除标准（按优先级排序）：
1. 口误/重复表达：同一意思说了两遍
2. 填充词：嗯、啊、然后就是、那个那个
3. 卡顿段落：逻辑断裂、说到一半改口
4. 冗余铺垫：说正事前的过多废话
5. 离题内容：与视频主题无关的闲聊

输出格式（严格 JSON，不要任何其他内容）：
{
  "deletions": [
    {
      "segment_ids": [3, 4],
      "start": 8.5,
      "end": 12.3,
      "reason": "重复表达，'然后就是说'后面内容与前句重复",
      "category": "redundant",
      "confidence": 0.92
    }
  ],
  "summary": "共发现 X 处建议删除，预计剪辑后视频从 Xmin 缩短至 Xmin"
}
```

**分析模式：**

|模式|触发方式|说明|
|---|---|---|
|全量分析|点击"全部分析"|分析完整字幕|
|片段分析|在文字稿中选中文本 → 点击"分析选中"|只分析选中范围|
|二次分析|修改完标记后再次触发|结果合并进现有标记列表|

**结果合并规则：**

- 新分析结果与现有标记重叠超过 50%：视为同一处，更新 confidence
- 无重叠：追加到列表
- 人工手动添加的标记：永远不被 AI 覆盖，标注为 `source: "human"`

### 3.5 模块 4：审核页（Step 3 & 4）

这是系统的核心交互区域。

#### 3.5.1 文字稿视图

- 按段落展示转录文本，每段落显示起始时间戳
- 被标记删除的文字：**红色高亮 + 删除线**
- 鼠标悬停标记区域：显示 tooltip（删除理由、置信度、来源）
- 点击任意时间戳：左侧原始视频跳转到对应位置

**交互操作：**

- **右键点击标记区域**：弹出菜单
    - "移除此处标记"（保留该片段）
    - "查看原因"
    - "定位到视频"
- **鼠标选中任意文字**：弹出操作浮层
    - "标记为删除"（新增删除标记）
    - "分析此段"（触发片段分析）

#### 3.5.2 删除片段列表（右侧面板）

每条记录显示：

```
[AI] 00:08 - 00:12  "然后就是说嗯那个..."
     理由：填充词堆积  置信度：91%
     [▶ 定位] [✕ 移除]

[手动] 00:45 - 00:52  "这个我们等下再说"
     [▶ 定位] [✕ 移除]
```

支持：

- 按类别筛选（填充词 / 重复 / 卡顿 / 手动添加）
- 按置信度排序
- 批量移除

#### 3.5.3 手动添加删除标记

**方式一**（文字稿选中）：选中文字 → 点击浮层"标记为删除"

**方式二**（时间轴输入）：在列表下方点击"手动添加" → 输入开始/结束时间

**方式三**（视频拖拽）：在左侧原始播放器的进度条上拖拽选择时间范围 → 点击"标记此区间"

### 3.6 模块 5：剪辑预览（Step 5）

**触发时机：**

- 每次审核页标记变更后，提供"更新预览"按钮（不自动触发，避免频繁调用 FFmpeg）
- 用户主动点击"生成预览"

**FFmpeg 处理逻辑：**

```python
# 根据删除标记列表，计算需要保留的时间段
# 例：删除 [8.5-12.3, 45.0-52.0]
# 保留：[0-8.5, 12.3-45.0, 52.0-end]

# FFmpeg 命令（concat 方式）
segments = compute_keep_segments(deletions, duration)
concat_filter = build_concat_filter(segments)
cmd = f"ffmpeg -i input.mp4 {concat_filter} output_preview.mp4"
```

**预览视频特性：**

- 分辨率降低（720p），加快生成速度
- 右侧播放器实时更新
- 预览视频在剪辑点处支持"跳转原片对应位置"（方便审核衔接是否自然）

**同步功能：**

- 左右两个播放器支持"同步播放模式"（原片 vs 剪辑后同步对比）

---

### 3.7 模块 6：导出（Step 6）

**导出选项：**

- 分辨率：原始 / 1080P / 720P
- 格式：MP4（H.264）/ MP4（H.265，更小体积）
- 是否嵌入字幕（SRT 硬字幕 / 软字幕 / 不嵌入）

**FFmpeg 导出命令（示例）：**

```bash
ffmpeg -i input.mp4 \
  -filter_complex "[0:v]trim=start=0:end=8.5,setpts=PTS-STARTPTS[v1]; \
                   [0:a]atrim=start=0:end=8.5,asetpts=PTS-STARTPTS[a1]; \
                   [v1][a1]concat=n=1:v=1:a=1[outv][outa]" \
  -map "[outv]" -map "[outa]" \
  -c:v libx264 -crf 18 -preset fast \
  -c:a aac -b:a 192k \
  output_final.mp4
```

**导出后：**

- 提供下载链接，文件保存到本地
- 同时导出审核记录（JSON），记录所有删除操作，方便复盘或重新处理

---

### 3.8 模块 7：二次分析区

位置：审核页上方工具栏区域

**功能：**

```
[二次分析]  ○ 分析全部  ● 分析选中片段   [分析风格: 严格 ▼]   [执行分析]
```

- **分析全部**：重新分析完整字幕，结果与现有标记合并（不覆盖人工标记）
- **分析选中片段**：先在文字稿中选中文本范围，再执行，只分析选中范围
- **分析风格**：
    - 保守：只删明显废话（适合内容密度高的视频）
    - 标准：默认
    - 激进：大量删减，追求精炼（适合长视频提取精华）

分析完成后，新增标记在列表中用"✨ 新增"标签高亮显示，便于用户只关注新变化。

## 四、后端 API 设计

### 4.1 接口列表

```
# 任务管理
POST   /api/tasks/upload              上传视频，创建任务
GET    /api/tasks/{task_id}           获取任务详情（状态、字幕、标记）
DELETE /api/tasks/{task_id}           删除任务及文件

# 转录
POST   /api/tasks/{task_id}/transcribe   手动触发转录（一般自动触发）
GET    /api/tasks/{task_id}/transcript   获取转录结果

# AI 分析
POST   /api/tasks/{task_id}/analyze   触发分析
Body: { "mode": "full" | "segment", "start": 0, "end": 120, "style": "standard" }

# 标记管理
GET    /api/tasks/{task_id}/deletions           获取所有删除标记
POST   /api/tasks/{task_id}/deletions           新增标记（人工）
DELETE /api/tasks/{task_id}/deletions/{del_id}  移除标记
PATCH  /api/tasks/{task_id}/deletions/{del_id}  修改标记时间范围

# 剪辑
POST   /api/tasks/{task_id}/preview    生成预览（低码率）
POST   /api/tasks/{task_id}/export     导出最终视频
Body: { "resolution": "1080p", "format": "h264", "subtitle": "none" }

# WebSocket
WS     /ws/{task_id}                   实时推送任务进度
```

### 4.2 WebSocket 消息格式

```json
{
  "event": "progress",
  "stage": "transcribing",       // uploading | transcribing | analyzing | previewing | exporting
  "progress": 45,                // 0-100
  "message": "正在转录音频... 45%",
  "data": {}                     // stage 完成时携带结果数据
}
```

## 五、数据模型

```python
# Task
class Task:
    id: str                  # UUID
    status: TaskStatus       # 枚举：idle/transcribing/analyzing/ready/exporting/done/error
    video_path: str          # 原始视频路径
    preview_path: str        # 预览视频路径
    export_path: str         # 导出视频路径
    duration: float          # 视频时长（秒）
    created_at: datetime
    updated_at: datetime

# Segment（转录片段）
class Segment:
    id: int
    task_id: str
    start: float
    end: float
    text: str
    confidence: float

# Deletion（删除标记）
class Deletion:
    id: str                  # UUID
    task_id: str
    start: float
    end: float
    segment_ids: List[int]   # 涉及的 Segment id
    reason: str
    category: str            # redundant/filler/stutter/offtopic/manual
    confidence: float
    source: str              # "ai" | "human"
    created_at: datetime
```

## 七、关键技术风险与对策

|风险|影响|对策|
|---|---|---|
|MiniMax ASR 长视频超时|转录失败|前端切分为 <5min 音频片段，分批调用|
|FFmpeg 在 Windows 环境缺失|用户本地无法运行|打包时内置 FFmpeg 二进制，或提供安装脚本|
|剪辑点衔接不自然|用户体验差|在删除点前后各保留 0.1s 淡出/淡入，或 AI 分析建议保留过渡词|
|大文件上传慢|用户等待|后端支持 chunked upload，前端显示实时进度|
|并发多任务资源占用|FFmpeg 吃满 CPU|MVP 阶段限制同时只处理 1 个 FFmpeg 任务，队列排队|
