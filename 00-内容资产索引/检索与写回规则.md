# 检索与写回规则

## `/script` 检索顺序

1. 查 `00-内容资产索引/内容主索引.md`，判断是否已有同类选题、历史数据和可复用资产。
2. 查 `02-素材知识库/`，优先复用核心概念、金句、案例和结构模板。
3. 查 `03-已发布归档/已发布成品/` 确认实际发布文案，再查 `04-数据与复盘/` 确认数据表现。
4. 最后才查 `深度思考/`、`碎碎念/`、`Clippings/` 等低优先级目录。

已发布资产边界：

- 实际发布文案只从 `03-已发布归档/已发布成品/` 读取。
- 播放、完播、收藏、分享、涨粉等指标只从 `04-数据与复盘/` 读取。
- `03-已发布归档/草稿归档/` 已删除，不得重新创建，也不作为内容检索入口。
- 知识库外层的历史过程稿备份属于冷备份，不进入默认检索；只有用户明确要求恢复或追溯某个版本时才读取。

脚本文件顶部必须记录：

```text
content_id:
复用素材:
参考数据:
当前状态:
```

## `/title` 要求

- 必须读取 `05-方法论沉淀/标题方法论/`。
- 如果标题方法论为空，先基于高数据作品生成基础公式，再给标题。
- 标题结果要区分抖音和小红书，不混用平台语气。

## `/hook` 要求

- 必须读取 `05-方法论沉淀/开头黄金5秒/`。
- 开头必须独立承载：观众痛点、内容对象、继续看的理由。
- 不默认观众理解 `workflow`、`agent`、`harness` 等术语，必须先用大众问题打开。

## `/review` 写回要求

复盘输出必须包含：

- `content_id`
- 数据判断：传播、完播、收藏、涨粉分别好坏
- 失败或成功原因
- 是否写回素材库
- 是否更新方法论
- 下一条选题建议

## `/ingest` 来源入库要求

1. 只处理 `06-来源原文库/` 内的来源文件。
2. 先更新 `06-来源原文库/SOURCE_REGISTRY.md`，记录来源类型、状态和抽取状态。
3. 抽取结果只能写入 `02-素材知识库/` 或 `05-方法论沉淀/`。
4. 原始来源正文不改写。
5. 每次入库都追加 `00-内容资产索引/log.md`。

## `/lint` 健康检查要求

1. 按 `00-内容资产索引/lint-checklist.md` 检查。
2. 检查范围包括主索引、来源原文库、素材知识库、方法论、数据复盘和搜索卫生。
3. 默认只输出问题和建议，不大规模改写旧内容。
4. 数据冲突以 `04-数据与复盘/` 为准。
