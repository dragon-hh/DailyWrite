## 文案内容


YC CEO Garry Tan  
开源了一个  
叫 GStack 的东西  
11 天，2 万 Star

50 天内  
他用这套配置  

写了 1 万行代码  
100 个 Pull Request

有人说  
这是开启了"上帝模式"  
有人说  
这是最好的 skill

GStack 是由  
Garry 创建的  
Claude Code  
开源技能包  
核心思路很简单

通过切换思维模式  
让 AI  
像一个完整的  
工程组织一样运作

具体流程如下
构思  
计划 
构建 
审查
测试
发布
反思


在这个流程中  
每个步骤  
都会为下一个步骤  
提供上下文和输入

GStack  
一共包含 28 个 Skill  
这些 Skill 被划分为  
核心冲刺流程  
和高级工具两大类

GStack 通过 Skill  
把 AI 切换成不同角色  
你说一句话  
AI 换上对应的大脑

比如你想做一个功能

先输入  
/plan-ceo-review  
它就变成创始人视角  
帮你审视  
你是不是在做正确的事

输入  
/plan-eng-review  
又切换成工程经理视角  
帮你锁定架构  
数据流、边界条件

写完代码之后  
输入 /review  
它立刻变成一个  
被生产事故毒打过的  
偏执工程师  
专门找那些能过 CI  
但会在线上爆掉的 bug

发布之前  
再输入 /qa  
它就自动打开浏览器  
逐页帮你跑一遍测试

Garry 自己说  
这些 Skill  
让我可以告诉模型  
我现在需要  
什么样的大脑

当你在规划功能时  
调用 CEO 模式  
在写代码时  
切换成工程模式  
在发布前  
启动审查模式

GStack 真正的价值  
不是某一个具体的命令  
而是把模糊的隐性知识  
变成可调用的函数  
这套方法论

我们正处于一个阶段  
流程带来的边际收益  
往往大于  
切换模型带来的边际收益

模型是引擎  
Skill 是变速箱
