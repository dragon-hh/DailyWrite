Claude Code 刚出了一个功能，叫 Workflow。
它把 Claude Code 从单兵作战，变成一个会自己编写流程、编排agent的超级系统。
上期视频我们演示了claudecode内置的deep research的workflow
这期视频我们写一个我们自定义的workflow-三省六部workflow。
具体的工作流程是这样的
====================  
第一阶段：任务归一化  
====================  
  
首先读取用户输入的任务描述。输入可能是自然语言、结构化对象、代码任务、研究任务、写作任务、分析任务、规划任务或其他任意形式。  
  输入归一化为一份标准任务说明

【第二阶段：中书省】 一个 agent 负责理解任务，将其拆解为若干并发可执行的子任务，输出一份结构化的执行计划，包含每个子任务的目标和预期产出。 【第三阶段：门下省】 一个独立的 agent 扮演批评者，对执行计划进行审驳：检查是否有遗漏、逻辑矛盾、或不合理的拆解。如果计划不通过，返回具体的修改意见，让第一阶段重新起草，循环往复直到通过为止。为防止无限循环，设置一个重试上限（建议 5 次），超出上限后门下省必须给出"带保留意见的通过"而非继续驳回。 【第四阶段：尚书省 + 执行】 计划通过后，根据计划中的子任务数量，并发启动对应数量的子 agents 分别完成各自的子任务。所有子任务完成后，由一个聚合 agent 将结果整合为统一的最终输出。 约束与要求： - 三个阶段严格串行，下一阶段必须在上一阶段完成后才能开始 - 子任务的数量和内容完全由第一阶段根据具体任务动态决定，不要预设固定结构 - 如果任务本身很简单，第一阶段可以决定只拆出一个子任务，跳过并发直接执行 - workflow 通过 args 接收任务描述，方便复用

第五阶段：御史台 —— 最终验收  
====================  
  
第四阶段完成后，必须启动一个独立的「御史台」验收 Agent。  
  
御史台不得参与前面的计划起草、计划审查、子任务执行或结果聚合。  
  
御史台只负责从最终交付质量角度进行独立验收。  
  
御史台需要对照内容检查最终输出
