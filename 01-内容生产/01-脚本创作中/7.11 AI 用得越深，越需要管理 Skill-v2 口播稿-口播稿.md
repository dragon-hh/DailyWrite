我刚刚把电脑里的 Skill
全扫了一遍，
结果有点离谱。

73 个项目，
接近 600 个 Skill。

有些是全局的，
有些只装给
Claude Code，
有些在 Codex、
OpenClaw 里，
还有一些
只在某个项目里生效。

最麻烦的不是数量多。

是我已经开始说不清，
哪个 AI 到底会什么了。

所以我把一个开源的
Skill 管理项目
拉到了本地。

它是一个本地
Skill 控制台。
不同 Agent 装了什么、
每个项目装了哪些 Skill，
一眼就能看清。

目前支持
所有主流 Agent 平台，
同时接入了
各个大厂公开
Skill 仓库。

点击即可快速安装
对应的 Skill。

点开 Skill，
既能看原文件，
也能让 AI 解释用途。

以前我也觉得，
Skill 跟插件差不多，
看到有用的就装。

但装到几百个以后，
我才发现，
安装只是最简单的一步。

一个写作 Skill
放在写作相关的项目里，
是经验。

塞进所有项目里，
就是噪音。

代码、写作、数据分析，
需要的能力
根本不是一套。

所以现在，
我会把真正通用的 Skill
放进中央技能库，
再按 Agent 和项目
分配过去。

不过这个开源项目
要真正放进我的工作流，
还得再改一轮。

原版在 Windows 上，
生成中文解释
会一直转圈，
还集成了 WorkBuddy、
OpenCode 等几十个
我不太用的平台，
非常冗余。

所以我让 Codex
修好 Bug，
隐藏不用的平台，
再调整一下配色。

到这一步，
这套 Skill 管理流程
才真正跑通。

给大家看下前后对比。

Skill，
让 AI 复用你的经验。

但当 Skill
增长到几百个以后，
管理决定了这些经验
到底是能力资产，
还是一堆散落在硬盘里的
Markdown 文件。

如果你也同时在用
Claude Code、
Codex 或
OpenClaw，
原项目地址
和我的改造思路，
我整理好了。

需要的朋友
在评论区见了，
记得点赞、收藏、关注。
