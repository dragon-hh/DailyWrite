DeepSeek Harness,以后很可能会成为国内使用最广泛的harness。

三天前,DeepSeek 干了一件比发布新模型更狠的事——开源了自己的 Agent,DeepSeek Harness。不到三天,GitHub 标星破十万。这个动作的意思是,DeepSeek 不再只跟你卷参数和跑分了,现在要卷"模型怎么被用起来"这一层,这恰好是过去一年 Claude Code 这类产品建立护城河的地方。

先说人话,什么是 harness。这两年 AI 圈总说"模型即产品",但真相是,同一个模型,换一套 Harness,表现能差出十万八千里。DeepSeek 官网自己放了一条公式:Agent 等于 Model 加 Harness,模型是大脑,harness 就是手和脚,二者组合起来才能真正干活。

DeepSeek Harness 的设计哲学一句话:一切皆插件。模型适配器是插件,工具注册是插件,会话管理是插件,连智能体循环本身都是插件,没有一个焊死的核心。


底层靠一个叫 Cordis 的内核撑着，
这个内核干的事情极其克制，只负责插件的加载、卸载和依赖管理，其他的什么都不管。
最牛的是，可以在Agent运行的过程中，随时更换插件，还能保证Agent运行状态不崩。
核心是两个特性：
Temporal composability，时间可组合性，也就是 一个插件卸载之后，它之前产生的副作用能不能完整撤销。
Spatial composability，空间可组合性， 一个插件如果依赖其他插件，当其他插件出现、消失、改变时，它能不能动态地重新处理自己的依赖

所以整个Cordis的内核本身，是为了让Agent在运行过程中不断的给自己开发、安装卸载插件，不断的插拔自己给自己添加和删除能力，从而形成某种意义的自进化。

这也是我觉得整个 DeepSeek Harness 里最特别的一点:
它有个"创造模式",能让 Agent 检查自己正在运行的插件和能力,发现自己缺什么,当场给自己造一个插件,直接挂到正在跑的流程里接着用。
打个比方,就像干活干到一半发现手边没有扳手,索性自己现场做一把,装上继续干。你可以直接跟它说,给我做一个只能读代码、不能改文件的安全审计模式,或者给我做一个接了公司内部搜索、固定用某个模型的研究 Agent,它自己就能把这套插件造出来挂上去。

很多人第一反应拿它跟 Claude Code 比。说实话没必要唱衰谁,思路不一样。Claude Code 相对固定,你在它划好的框架里接工具;dsh 反过来,从模型适配器到沙箱到界面,理论上每一层都能单独换掉。一个开源、可拆、还在长身体,一个闭源、集成度高、已经很成熟。

最后说句实话,这套东西对普通用户其实不太友好——开发者黑话多,上手门槛高,界面也谈不上好用,每一步都挺劝退的。但 DeepSeek 这个团队,可能本来就更在意搞研究、搞探索,不是把它当成一个要伺候普通用户的产品在做。想尝鲜的话,一行命令 npx @deepseek-ai/dsh web 就能跑起来。
