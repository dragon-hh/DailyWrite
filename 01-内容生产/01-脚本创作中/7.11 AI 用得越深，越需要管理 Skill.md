
标题：AI 用得越深，越需要管理 Skill

你给 AI 装过多少个 Skill？

我刚刚扫描了一下自己的电脑，发现 73个项目里，竟然散落着将近 600个 Skill。

更麻烦的是，有些属于全局，有些只给 Claude Code，有些装在 Codex、OpenClaw 里，还有一些只应该在某个项目中生效。

装得越多，最后越不知道：哪个 AI 到底会什么。

所以我最近把一个开源skill管理项目拉到了本地。

它相当于一个 Agent Skill 管理控制台，可以把电脑里不同 Agent、不同项目的 Skill，集中到一个界面里查看。

比如这里，我可以直接看到 Claude Code、Codex、OpenClaw、Cursor 等平台分别安装了哪些 Skill。

也可以扫描本地项目，快速发现每个项目私有的 Skill。

如果某个项目里的 Skill 很通用，我可以把它导入中央技能库，再按需分配给不同的 Agent。

这里有个很重要的区别。

Skill 不是装得越多越好。

写作项目、编程项目、数据分析项目，需要的能力完全不同。把几百个 Skill 一股脑塞给 AI，只会增加冲突、干扰和维护成本。

真正合理的方式，是让正确的 Skill，只出现在正确的平台和正确的项目里。

这个应用还可以同步多个公开 Skill 仓库。

比如我这里同步微软的 Skill 源后，看到了 400 多个 Skill。点进去不仅能看原始文件，还可以让 AI 先解释：这个 Skill 是做什么的、适合什么场景、值不值得安装。

不过原项目直接放到我的 Windows 环境里，并不是完全能用。

我重新做了界面配色，补上了平台隐藏和排序，还修复了本地项目扫描，以及中文长文本生成 AI 解释时卡住的问题。

这也是我现在越来越喜欢开源项目的原因。

开源最有价值的地方，不只是免费，而是你可以借助 AI，把一个通用工具继续改造成真正适合自己工作流的生产工具。

模型决定 AI 有多聪明。

Skill 决定 AI 能不能复用你的经验。

而 Skill 管理，决定这些经验最终是散落的文件，还是你可以不断积累的能力资产。

如果你已经在同时使用 Claude Code、Codex 或 OpenClaw，我会把原项目地址和这次改造的思路放在置顶评论。
