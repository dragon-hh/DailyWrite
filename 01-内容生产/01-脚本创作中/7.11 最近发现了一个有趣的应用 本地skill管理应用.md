# AI 用得越深，越需要管理 Skill

## DBS 内容诊断

- 选题：本地 AI Skill 管理平台实测与改造
- 内容形式：露脸口播 + 屏幕录制
- 推荐平台：抖音短视频为主，小红书同步图文版
- 内容目标：展示对 Agent 工作流的真实理解，建立“会使用、会判断、会改造”的 AI 博主人设

| 维度    | 判断     | 诊断                                                       |
| ----- | ------ | -------------------------------------------------------- |
| 文字洁癖  | 警告     | 原稿是连续的功能罗列，“有趣、好用、方便”等判断缺少证据，容易拍成普通软件介绍。                 |
| 封面与标题 | 警告     | “最近发现了一个有趣的应用”没有利益点，也没有冲突。最强画面应该是“32 个项目、近 300 个 Skill”。 |
| 表达效率  | 警告     | 平台列表和仓库列表过长。正文只保留平台管理、项目扫描、Skill 解释三个能力。                 |
| 认知落差  | 通过     | 同类内容大多讲“去哪里安装 Skill”，很少讲 Skill 的作用域、冲突和能力资产管理。           |
| AI 辅助 | 实测型工作流 | 真实扫描本机数据，录制三个核心操作，再补充改造前后的 Bug 对比。                       |

一句话结论：不要把这条视频做成“我发现了一个工具”，要做成“当 Skill 越装越多，AI 用户必须开始管理自己的能力资产”。

## 核心观点

模型决定 AI 有多聪明。

Skill 决定 AI 能不能复用你的经验。

而 Skill 管理，决定这些经验最终是散落的文件，还是可以持续积累的能力资产。

## 口播稿

你给 AI 装过多少个 Skill？

我刚刚扫描了一下自己的电脑，发现 32 个项目里，竟然散落着将近 300 个 Skill。

更麻烦的是，有些属于全局，有些只给 Claude Code，有些装在 Codex、OpenClaw 里，还有一些只应该在某个项目中生效。

装得越多，最后越不知道：哪个 AI 到底会什么。

所以我最近把一个开源项目拉到了本地。

它相当于一个 AI Skill 管理控制台，可以把电脑里不同 Agent、不同项目的 Skill，集中到一个界面里查看。

比如这里，我可以直接看到 Claude Code、Codex、OpenClaw、Cursor 等平台分别安装了哪些 Skill。

也可以扫描本地项目，快速发现每个项目私有的 Skill。

如果某个项目里的 Skill 很通用，我可以把它导入中央技能库，再按需分配给不同的 Agent。

这里有个很重要的区别。

Skill 不是装得越多越好。

写作项目、编程项目、数据分析项目，需要的能力完全不同。把几百个 Skill 一股脑塞给 AI，只会增加冲突、干扰和维护成本。

真正合理的方式，是让正确的 Skill，只出现在正确的平台和正确的项目里。

这个应用还可以同步多个公开 Skill 仓库。

比如我这里同步微软的 Skill 源后，看到了 400 多个 Skill。点进去不仅能看原始文件，还可以让 AI 先解释：这个 Skill 是做什么的、适合什么场景、值不值得安装。

不过原项目直接放到我的 Windows 环境里，并不是完全能用。

我重新做了界面配色，补上了平台隐藏和排序，还修复了本地项目扫描，以及中文长文本生成 AI 解释时卡住的问题。

这也是我现在越来越喜欢开源项目的原因。

开源最有价值的地方，不只是免费，而是你可以借助 AI，把一个通用工具继续改造成真正适合自己工作流的生产工具。

模型决定 AI 有多聪明。

Skill 决定 AI 能不能复用你的经验。

而 Skill 管理，决定这些经验最终是散落的文件，还是你可以不断积累的能力资产。

如果你已经在同时使用 Claude Code、Codex 或 OpenClaw，我会把原项目地址和这次改造的思路放在置顶评论。

## 画面顺序

1. 开头直接展示“32 个项目、近 300 个 Skill”的扫描结果。
2. 切换 Claude Code、Codex、OpenClaw，展示不同平台安装的 Skill。
3. 打开项目技能库，展示项目扫描和项目级 Skill。
4. 打开微软 Skill 源，展示 Skill 数量、详情和 AI 解释。
5. 展示改造前后对比：目录无法添加或扫描、AI 解释持续转圈、修复后正常工作。
6. 结尾回到中央技能库，用“能力资产”完成观点升维。

## 事实边界

- 项目地址：https://github.com/iamzhihuix/skills-manage
- 使用“公开 Skill 仓库或发布源”，不要笼统说成与所有大厂官方合作。
- “400 多个 Skill”是本次同步后的页面结果，数量可能随仓库更新变化。
- 不要说“大部分 Agent 都直接读取 `.agents/skills/`”。更准确的说法是：以中央技能库作为统一来源，再根据不同 Agent 的目录规则进行安装或关联。
- Claude Code 除了原生 Skill 目录，还会展示插件市场中的只读 Skill，这些条目不能完全按普通 Skill 管理。
