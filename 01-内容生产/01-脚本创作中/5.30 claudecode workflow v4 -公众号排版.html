Claude Code Workflow，可能是下一个 MCP 时刻

Claude Code 刚出了一个功能，叫 Workflow。

我用它跑了一次 deep-research，25 分钟，104 个 agent，280 万 token。

跑完我只有一个感觉，这项技术可能会成为 Anthropic 继 MCP、Skill 之后的又一个关键创新。

它让 Claude Code 从「自己写代码」，变成「组织一群 agent 干活」。

这不是多开几个窗口那么简单，而是把复杂任务变成可审计、可复用、可版本控制的执行系统。

提到工作流，大家肯定会想到 Dify、Coze。

但 Claude Code 这里的 Workflow，不太一样。

它不是让你在画布上拖几个节点，而是你描述一个任务，Claude Code 会生成一个 JS 编排脚本，把任务拆成阶段，把不同阶段分给不同 agent，然后在后台协调几十到上百个 subagent，最后收敛成一个结果。

这个变化挺关键的。

Prompt 不再是终点。
Workflow 本身开始变成资产。

以前所谓的 agent team，很多时候还是临时拼出来的。

你这次让它这么分工，下次它可能换一种分工。你这次让它查资料，下次它可能少验证一步。整个过程很依赖模型临场发挥。

Workflow 把这件事往前推了一步，它把临时协作固化成代码，让你能看到它分了哪些阶段，开了多少 agent，预算怎么花，最后怎么收敛。

拿官方内置的 deep-research workflow 举例，它大概是五段式。

1、Scope，把你的问题拆成 5 个不同角度的搜索词，避免后面只沿着一个方向挖。

2、Search，5 个 agent 并发搜索，每个角度各找 4 到 6 条结果，互不等待。

3、Fetch + Extract，去重后抓取最多 15 个网页，每个页面提取 2 到 5 条可证伪的具体结论。

4、Verify，每条结论再派 3 个持怀疑态度的 agent 独立找反证，2 票反对就淘汰。

5、Synthesize，把通过验证的结论合并，按置信度排序，写成带来源引用的最终报告。

我这次就是用 deep-research 去调研 Claude Code 最新的 Workflow 功能，然后让它写一篇文章。

它启动了完整流程，最后一共花了 25 分钟，动用了 104 个 agent，消耗 280 万 token，验证了 25 条声明。

最后输出的东西，完成度确实不错。

它不只是把网上内容拼一遍，而是把 Workflow 的核心定位、和 Agent Teams 的区别、运行时限制、内置 deep-research 的阶段拆解，都整理得比较清楚。

这次实测数据

25 分钟 · 104 个 agent · 280 万 token

很爽，但也很贵。所以预算控制会变得非常重要。

这时候肯定有人要问，这么玩，token 是不是要爆炸。

坦率的讲，会。

多 agent 听起来很爽，但没有预算控制，它就是 token 粉碎机。

所以 Workflow 里有一个很关键的设计，就是可以直接在任务里写预算，比如 workflow 100k。

Claude Code 会根据这个预算，规划 agent 数量、每个阶段的深度，以及最后怎么收敛。

怎么用呢，其实就两种方式。

第一种，在提示词里直接提到 workflow 这个词。

第二种，使用 /effort ultracode 开启。

然后用 /workflows 查看当前正在跑的工作流，包括每个阶段的执行情况和 agent 数量。

回到 Claude Code Workflow 这件事。

我觉得它不是一个普通的新功能。

它更像是一个信号，AI 编程正在从个人能力，转向组织能力。

以前我们问，一个模型能不能写代码。

后来我们问，一个 agent 能不能独立完成任务。

现在问题变了，一个系统能不能组织多个 agent，在预算内、可验证地完成复杂任务。

这可能才是 Workflow 真正有意思的地方。
它不是让 AI 更会单兵作战，而是让 AI 开始学会组织协作。
