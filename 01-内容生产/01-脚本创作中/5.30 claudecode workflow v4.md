##  Workflow，让Claude Code 从“自己写代码”，变成“组织 agent 干活”。
封面

![[image-20260531061628547.png]]
Claude Code 刚出了一个功能，叫 Workflow。
它让 Claude Code 从“自己写代码”，变成“组织 一群agent 干活”。
我用它跑了一次 deep-research，25 分钟，104 个 agent，280 万 token。
跑完我只有一个感觉：这项技术可能将成为Anthropic，继MCP、Skill之后的又一重大创新。

---
提到工作流，大家肯定会想到dify、coze。
但 Claude Code 这里的 Workflow，不太一样。

它是你描述一个任务，Claude 就会写一个 JS 编排脚本，把任务拆成阶段，把不同阶段分给不同 agent，在后台协调数十到数百个 subagent，最终交付结果，提升复杂长任务的可靠性。

---

听着是不是有点像以前的agent teams，workflow把以前的临时agent团队搭配，固化为代码，
把它变成一个**可审计、可复用、可版本控制**的东西，而不是每次都靠模型临场发挥。

---
拿官方内置的deep-research 这个工作流举例
![[image-20260530130912856.svg]]
主要分为五个阶段

-第一阶段 **多维拆解 (Scope)**— 把你的问题拆成5个不同角度的搜索词，确保后面不会只搜一个方向
    
- -第二阶段：**并发搜索 (Search)**— 5个 agent 同时去搜，每个角度各自找4-6条结果，互不等待
    
- -第三阶段：**去重提取 (Fetch+Extract)**— 去重后抓取最多15个网页，每个页面提取2-5条"可证伪的具体结论"
    
- 第四阶段：**交叉验证 (Verify)**— 每条结论派3个持怀疑态度的 agent 独立去找反证，2票反对就淘汰
    
- 最后是：**合并综合 (Synthesize)** — 把通过验证的结论合并、按置信度排序，写成带来源引用的最终报告

---
这时候一定有很多人问了，这么玩，我的token是不是要爆炸了。

多 agent 听起来很爽，但没有预算控制，它就是 token 粉碎机。

所以 Workflow 里有一个很关键的设计，是可以直接在任务里写预算，比如 `workflow 100k`。

Claude Code 会根据这个预算规划 agent 数量、每个阶段的深度和最后收敛方式。

---
说了这么多，workflow如何使用呢，
两种方法：
1. 在提示词里**直接提到 "workflow"** 这个词，此时workflow会变为彩色
2. 使用 /effort ultracode 开启

这样claude就会根据你的任务自动生成工作流程
使用 /workflows 可以查看你当前正在跑的工作流
包括每个阶段的执行情况，agent数量。

---

回到 Claude Code Workflow 这件事，
它不是一个新功能那么简单。
它是 AI 编程开始从个人能力，转向组织能力的信号。
以前我们问，一个模型能不能写代码。
后来我们问，一个 agent 能不能独立完成任务。
现在我们要问的是：**一个系统能不能组织多个 agent，在预算内、可验证地完成复杂任务。**
