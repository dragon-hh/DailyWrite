先看结论：竞争单位已经改变

从“单次回答质量”上移到“一个任务是否低风险、低返工地完成”。

03

九个值得关注的新观点

每个判断都附着行动含义，不把趋势停在概念层。

衡量单位从 token 单价变成每个成功任务的成本

只比较输入输出 token 价格已经失真。强模型单次更贵，却可能因少返工、少人工接管而拥有更低的 $/task。成本表至少要同时记录模型费、工具费、耗时、人工接管分钟数、成功率与返工次数。

下一步用同一真实任务做三组对照，统一成功条件。

Harness 正在成为模型能力的放大器

同一模型在不同框架中可能产生巨大差异。Compaction、长程推理、按需检索、工具调用、环境恢复与 harness 蒸馏都在说明：很多失败不是模型不够强，而是上下文过载、工具不足或用例范围失控。

判断先优化任务结构，再考虑换模型。

Agent 的产品形态从聊天框变成异步控制塔

远程调度、语音驱动、后台检查、堆叠会话、跨 session 摘要、持久化 memory 与 Project，意味着用户不必一直盯着窗口。新交互重点是启动、介入、进度、恢复与验收。

产品问题何时需要人回来，而不是如何让人一直在线。

安全边界从“每次弹窗确认”转向“环境先限权”

Anthropic 工程复盘称用户会批准约 93% 的权限请求，审批疲劳会削弱弹窗价值。更可靠的方向是 sandbox、VM、文件系统边界、egress control 与审计日志先限制爆炸半径。

官方核验Auto mode 是 defense-in-depth 的一层，不能替代确定性隔离。

AI 写代码之后，真正稀缺的是可审查性

生成量上升后，人无法审查巨大 diff，也不能凭“看起来不错”验收。标准产线需要小批次变更、明确验收条件、自动测试、风险扫描、真人签字与可回放证据。

产线原则小 PR、独立测试、风险可回放。

企业落地首先是工作流与组织问题

先找杠杆最高的 10 个流程，把 agent 接进员工已有系统，比全员散点试验更有效。安装派对、同类榜样、在会议中直接展示 agent 工作，比抽象承诺“效率提升十倍”更能推动采用。

内容机会把采用手段本身做成教程。

最强模型做验证，便宜模型做生产

先用 frontier model 验证体验，需求成立后再优化 prompt、routing、harness、小模型与微调。生产架构逐渐变成：强模型负责决策、升级与验收，便宜模型负责批量执行。

官方核验OpenRouter 的 subagent / advisor 支持这类协作模式。

Agent-native 基础设施正在形成独立产品层

浏览器、沙箱、持久化状态、预算控制、追踪、回放与人工接管正在被拆成专门产品。做出一个 agent，与让它在生产环境持续工作，已经是两件不同的事。

观察基础设施决定长任务能否持续、可控、可恢复。

专业能力更值钱，但专家培养链可能断裂

AI 能替代大量初级工作，但检查 AI 输出依赖多年经验。每家公司削减初级岗位或许局部理性，集体却可能失去培养下一代专家的渠道。更该讨论如何保留练基本功、人工复盘与判断力训练。

议题转向不只问“替代谁”，还要问“专家从哪里来”。

05

这周可以立刻做

四个最短路径：都有强对照画面、真实结果与可下载模板。

01

建立「每任务成本表」

固定一个真实任务，用三套模型或框架跑完；把人工接管、返工、成功条件一起记账。

交付：$/task 模板 + 三组结论
04

搭最小安全沙箱

逐一测试文件读取、网络外传、工作区写入与危险命令，再加 sandbox、allowlist、只读挂载和审计日志。

交付：四层安全基线清单
06

给浏览器 Agent 装回放

记录 DOM、console、network、点击轨迹和 session replay，让 agent 从 trace 找根因并复测。

交付：可观测性最小配置
07

做 Skill / Memory 清理员

扫描重复、过期、冲突与从未触发项，只生成候选清单，人确认后再修改。

交付：健康评分 + 每周 curator 任务
06

十个偏实战选题

点击展开问题、演示、交付物与钩子画面。

01别再比较 token 单价：我给 3 个 Agent 做了一张“每任务成本表”优先拍

核心问题：便宜模型是否真的更省钱？

演示：同一真实任务跑 3 套模型 / 框架，记录成本、耗时、成功率、返工与人工接管。

交付物：可复用的 $/task 记账模板和结论表。

钩子：三个账单都很便宜，但只有一个真正交付成功。

02同一个模型，换个 Harness 为什么能差这么多？第二梯队

核心问题：模型能力与框架能力如何拆开测？

演示：固定模型和仓库，用不同 harness 完成同一 issue；统一 prompt、预算和验收。

交付物：A/B 测试协议、成功条件、上下文与工具调用对比。

钩子：模型没换，成功率却明显变化。

03让 3 个 Coding Agent 接力干活：Issue → Session → PR → 人审第二梯队

核心问题：多 agent 怎样避免互相覆盖和无限解释上下文？

演示：规划 agent 拆 issue，执行 agent 各开 session，审查 agent 看 stacked PR。

交付物：任务交接模板、状态字段和失败恢复方式。

钩子：人没复制历史记录，三个 session 仍然接上了。

04Agent 安全别只靠“允许 / 拒绝”：搭一个最小安全沙箱优先拍

核心问题：为什么每次点允许并不等于安全？

演示：测试读取、外传、写入和危险命令；加入 sandbox、egress allowlist、只读挂载和审计日志。

交付物：四层安全基线检查表。

钩子：模型想执行恶意指令，但环境根本不给出口。

05AI 一次改 1000 行代码，怎么让人敢合并？第二梯队

核心问题：如何把巨大 diff 拆成能审查的小块？

演示：按数据层、API、接线、UI 拆成 4 层 stacked PR，各自测试和回滚。

交付物：PR 拆层规则、审查人分工、自动检查清单。

钩子：左边 1000 行巨型 PR，右边 4 个一眼能审完的小 PR。

06给浏览器 Agent 装“行车记录仪”：失败后能完整回放优先拍

核心问题：为什么浏览器失败后常只剩“元素没找到”？

演示：记录 DOM、console、network、点击轨迹和 replay；让 agent 从 trace 找根因再复测。

交付物：浏览器 agent 可观测性最小配置。

钩子：开启回放前靠猜，开启后 30 秒定位。

07Skill 越装越多，Agent 为什么反而变笨？做一个自动清理员优先拍

核心问题：skills 和 memory 如何产生 slop？

演示：扫描重复、过期、冲突和从未触发项；只产候选清单，人确认后再改。

交付物：健康评分、去重规则和每周 curator 任务。

钩子：删除 30% 垃圾能力后，任务成功率反而上升。

08大模型当主管，小模型当员工：真实任务省多少？第二梯队

核心问题：何时值得把执行委托给便宜模型？

演示：强模型拆解、升级与验收；小模型做摘要、抽取、改格式和重复实现。

交付物：路由决策树和五类“必须升级强模型”情况。

钩子：不是所有步骤都值得烧最贵的 token。

09会议纪要已经过时：让 Agent 在会议结束前交付结果观察后拍

核心问题：如何把会后待办变成会中完成？

演示：转录 → 行动项 → 邮件 / 文档 / 任务 → 负责人确认 → 写回系统。

交付物：一套有确认门的会议执行工作流。

钩子：会议结束时，8 条待办里已有 6 条完成。

10AI 写代码、AI 审代码后，人到底做什么？做一份验收规格观察后拍

核心问题：人类如何从盯实现转成定义结果？

演示：先写可观察标准、边界案例和禁止项，再让 agent 实现、预审，真人只走用户路径。

交付物：一页 acceptance spec 模板与前后对比。

钩子：不再告诉 AI 每一步怎么写，只定义什么结果才算完成。
