02 / SIGNALS

九个新判断

每个判断都落到一个操作原则。阅读方式不是「同意或不同意」，而是「下一次任务怎么验证」。

成本单位从 token 单价变成每个成功任务的成本

强模型单次调用更贵，但若少返工、少人工接管并能完成更难任务，最终 $/task 反而可能更低。

MEASURE同表记录：模型费、工具费、耗时、人工分钟、成功率、返工次数。不要拿一次账单替代完整交付成本。

Harness 正在成为模型能力的放大器

同一模型在不同框架里会出现巨大差异。上下文堆积、缺少按需检索工具、用例过宽，都会把模型能力吃掉。

PROTOCOL固定模型、任务、预算与验收测试，只替换 Harness。先优化任务结构，再决定是否换模型。

Agent 从聊天框变成异步控制塔

远程调度、后台检查、跨 session 摘要、持久化 memory 与 Project，正在把交互中心转向任务启动、介入、恢复与验收。

DESIGN为任务定义状态、介入门、恢复点和验收证据。不要要求人一直盯着对话窗口。

安全边界从「每次弹窗」转向「环境先限权」

用户会快速批准大量权限请求，审批疲劳让确认框失去意义。Auto mode 只能是防御纵深的一层。

CONTAIN优先配置 sandbox、VM、文件边界、egress control 与审计日志。环境不给出口，比提醒用户小心更确定。

AI 写代码之后，真正稀缺的是可审查性

生成量上升后，巨大 diff 和「看起来不错」都会压垮人审。小批次变更与可回放证据成为产线核心。

REVIEW拆小 PR、写验收条件、自动测试与风险扫描，最终由人签字。审查对象应是可观察结果，不是模型自述。

企业落地首先是工作流与组织问题

先找杠杆最高的十个流程，把 agent 接进现有系统；让同类榜样在真实会议里展示结果，比抽象宣传更能推动采用。

ADOPT从高杠杆流程和现场演示开始，不从「全员自由探索」开始。安装派对与可见的真实成果也是产品的一部分。

最强模型做验证，便宜模型做生产

先用最强模型验证体验与需求；成立后再优化 prompt、routing、Harness、小模型与微调。

ROUTE强模型拆解、升级判断、验收；便宜模型做摘要、抽取与重复实现。先证明任务值得做，再压低单位成本。

Agent-native 基础设施形成独立产品层

浏览器、沙箱、持久状态、预算、追踪、回放与人工接管，正在分离「做出 agent」和「让 agent 长期生产」两件事。

OPERATE长任务上线前，至少补齐隔离、追踪、回放、预算与人工接管。能跑一次，不等于能持续运行。

专业能力更值钱，但专家培养链可能断裂

AI 替代初级工作，却仍需要多年经验来检查输出。每家公司削减初级岗位都可能理性，集体却失去下一代专家。

TRAIN保留基本功练习、人工复盘和判断力训练，不只考核产出速度。把「会验收」当作需要被培养的专业能力。

01

02

搭最小安全沙箱

03

给浏览器 Agent 装回放

记录 DOM、console、network、点击轨迹和 session replay，再让 agent 定位失败。

04
