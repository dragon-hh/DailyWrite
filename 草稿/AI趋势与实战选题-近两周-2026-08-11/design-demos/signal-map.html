02

九个新观点

每个节点不是孤立新闻，而是一组信号汇成的判断。橙色短线标出从观察走向行动的落点。

01

衡量单位从 token 单价变成每个成功任务的成本

多份日报交叉信号成本模型

只比较输入输出 token 价格已经失真。强模型单次调用更贵，却可能因为少返工、少人工接管、能完成更难任务而拥有更低的 $/task。成本表至少应记录模型费、工具调用费、任务耗时、人工接管分钟数、成功率和返工次数。

判断采购与评测的最小单位应从“调用”升级为“成功交付”。
02

Harness 正在成为模型能力的放大器

日报与 Builders 观察上下文工程

同一模型在不同框架中可以出现巨大结果差异。Compaction、长程推理、按需检索、工具调用、环境恢复与 harness 蒸馏反复出现。很多失败不是模型不够强，而是上下文塞太多、缺少按需找信息的工具、同时覆盖太多用例。

判断先优化任务结构和信息供给，再决定是否换模型。
03

Agent 的产品形态从聊天框变成异步控制塔

部分能力官方核验交互范式

移动端远程调度、语音驱动、后台检查、堆叠会话、跨 session 摘要、持久 memory 和 Project，都说明用户不再需要一直盯着聊天窗口。新的交互重点是任务怎样启动、何时需要人介入、如何看进度、恢复上下文并验收。

判断Agent 产品的首页最终会更像任务控制台，而非空白输入框。
04

安全边界从“每次弹窗确认”转向“环境先限权”

Anthropic 官方核验安全

用户会批准约 93% 的权限请求，频繁弹窗造成审批疲劳。更可靠的方向是用 sandbox、VM、文件系统边界、egress control 与审计日志限制爆炸半径，再用模型分类器降低日常摩擦。Auto mode 只是防御纵深的一层。

判断安全设计要把“模型会不会做”改成“环境允许它做到哪”。
05

AI 写代码之后，真正稀缺的是可审查性

多项产品官方核验软件交付

堆叠 PR、可视化人审、Codex Security、Align Evals 与 agent issue 循环都在解决同一瓶颈：生成量上升后，人无法审查巨大 diff，也无法凭“看起来不错”判断结果。标准产线需要小批次变更、明确验收条件、自动测试、风险扫描、人工签字与可回放证据。

判断未来的开发速度由审查带宽和证据质量决定，而不只由生成速度决定。
06

企业落地首先是工作流与组织问题

行业观察组织采用

先找企业内部杠杆最高的 10 个流程，把 agent 隐形接入员工已有系统，比让所有人散点试验更有效。安装派对、同类榜样、会议现场直接展示 agent 工作，也比抽象宣讲“效率提升 10 倍”更能推动采用。

判断采用机制本身就是产品的一部分，也值得被做成可复制教程。
07

最强模型做验证，便宜模型做生产

OpenRouter 官方核验模型路由

先用最强 frontier model 验证体验，需求成立后再优化 prompt、routing、harness、小模型与微调。OpenRouter 的 subagent / advisor，以及日报中的 Sol 指挥 Luna，都体现“强模型做决策与验收、便宜模型做批量执行”。

判断模型不是单选题，而是一条按任务风险动态升级的供应链。
08

Agent-native 基础设施正在形成独立产品层

部分能力官方核验部分工具仅日报收录基础设施

Browser Run、Kitesurf、Dynamic Workers、Managed Deep Agents、LLM Gateway、Local Explorer 等工具共同补齐浏览器、沙箱、持久状态、预算控制、追踪、回放与人工接管。这意味着“做一个 agent”与“让 agent 持续在生产环境工作”已是两件事。

判断生产级 Agent 的护城河正在从 prompt 转向运行时与治理层。
09

专业能力更值钱，但专家培养链可能断裂

行业观察人才结构

AI 能替代大量初级工作，但检查 AI 输出依赖多年经验。每家公司削减初级岗位或许都理性，集体却可能失去培养下一代专家的渠道。内容不应只问“AI 替代谁”，还应讨论如何保留基本功、人工复盘与判断力训练。

判断组织需要把“练习机会”当成必须维护的认知基础设施。

04

这周可以立刻做

四项行动对应四个优先选题：都有强对比画面、真实结果与可下载模板。

01

建立每任务成本表

固定一个真实任务，跑 3 套模型或框架；同时记录总费用、耗时、成功率、返工和人工接管。

交付：$/task 记账模板
02

搭最小安全沙箱

逐项测试文件读取、网络外传、工作区写入和危险命令，再加 sandbox、egress allowlist、只读挂载和审计日志。

交付：四层安全基线
03

给浏览器 Agent 装回放

记录 DOM、console、network、点击轨迹和 session replay；让 agent 从 trace 找根因并复测。

交付：可观测性最小配置
04

做 Skill / Memory 清理员

扫描重复、过期、冲突与从未触发项，只生成候选清单，由人确认后再改。

交付：健康评分与每周任务

拍摄队列
01别再比较 token 单价：我给 3 个 Agent 做了一张“每任务成本表”+

核心问题便宜模型是否真的更省钱？

演示同一真实任务跑 3 套模型 / 框架，记录总成本、耗时、成功率、返工次数和人工接管。

交付物可复用的 $/task 记账模板与结论表。

钩子画面三个账单都很便宜，但只有一个真正交付成功。

本周优先
02同一个模型，换个 Harness 为什么能差这么多？+

核心问题模型能力与框架能力如何拆开测？

演示固定模型和仓库，用不同 harness 完成同一 issue；保持 prompt、验收测试与预算一致。

交付物A/B 测试协议、成功条件、上下文与工具调用对比。

钩子画面模型没换，成功率却明显变化。

第二梯队
03让 3 个 Coding Agent 接力干活：Issue → Session → PR → 人审+

核心问题多 agent 怎样避免互相覆盖和无限解释上下文？

演示规划 agent 拆 issue，执行 agent 各开 session，审查 agent 看 stacked PR，人只做最终验收。

交付物任务交接模板、状态字段和失败恢复方式。

钩子画面人没复制历史记录，三个 session 仍然接上了。

第二梯队
04Agent 安全别只靠“允许 / 拒绝”：搭一个最小安全沙箱+

核心问题为什么每次点允许并不等于安全？

演示测试文件读取、网络外传、工作区写入和危险命令；增加 sandbox、egress allowlist、只读挂载与审计日志。

交付物四层安全基线检查表。

钩子画面模型想执行恶意指令，但环境根本不给出口。

本周优先
05AI 一次改 1000 行代码，怎么让人敢合并？+

核心问题如何把巨大 diff 拆成能审查的小块？

演示一次功能改造拆成数据层、API、接线、UI 四层 stacked PR，每层独立测试和回滚。

交付物PR 拆层规则、审查分工与自动检查清单。

钩子画面左边 1000 行巨型 PR，右边 4 个一眼能审完的小 PR。

第二梯队
06给浏览器 Agent 装“行车记录仪”：失败后能完整回放+

核心问题浏览器自动化失败为何总只剩“元素没找到”？

演示记录 DOM、console、network、点击轨迹和 session replay；让 agent 从 trace 找根因再复测。

交付物浏览器 agent 可观测性最小配置。

钩子画面开启回放前靠猜，开启后 30 秒定位。

本周优先
07Skill 越装越多，Agent 为什么反而变笨？做一个自动清理员+

核心问题自动积累 skills 和 memory 如何产生 slop？

演示扫描重复、过期、冲突和从未触发技能；生成候选清理清单，人确认后再改。

交付物Skill / Memory 健康评分、去重规则与每周 curator 任务。

钩子画面删除 30% 垃圾能力后，任务成功率反而上升。

本周优先
08大模型当主管，小模型当员工：真实任务省多少？+

核心问题何时值得把执行委托给便宜模型？

演示强模型负责拆解、升级判断和验收，小模型做摘要、抽取、改格式与重复实现；记录节省和返工。

交付物路由决策树与“必须升级强模型”的五类情况。

钩子画面不是所有步骤都值得烧最贵的 token。

第二梯队
09会议纪要已经过时：让 Agent 在会议结束前交付结果+

核心问题如何把“会后待办”变成“会中完成”？

演示实时转录 → 识别行动项 → 生成邮件 / 文档 / 任务 → 负责人确认 → 写回系统。

交付物一套有确认门的会议执行工作流。

钩子画面会议结束时，不是多了 8 条待办，而是 6 条已经完成。

观察后再拍
10AI 写代码、AI 审代码后，人到底做什么？做一份验收规格+

核心问题人如何从“盯实现”转成“定义结果与测试产品”？

演示先写可观察的验收标准、边界案例和禁止项，再让 agent 实现、另一 agent 预审，真人按用户路径测试。

交付物一页 acceptance spec 模板与前后对比。
