# HTML 分析报告设计规格

这是一个面向 AI 工具实践者、个人开发者和内容创作者的中文长页面分析报告，最终用户会在笔记本浏览器中阅读，也可能截取局部用于选题讨论。报告不是新闻聚合页，也不是 SaaS dashboard。它的核心任务是把 17 份本地日报中重复出现的信号压缩成可行动判断：先告诉读者这两周真正发生了什么结构变化，再列出哪些工具值得马上实测，最后给出 10 个能直接拍摄或动手制作的实战选题。读者不需要从头读到尾也能快速抓住结论，但愿意深读时能看到证据、边界和下一步动作。

内容结构固定为：一屏结论摘要；来源覆盖与方法；九个新观点；工具雷达（A/B/C 三档）；“这周可以立刻做”的四项行动；十个实战选题；选题优先级矩阵；来源附录。页面必须明确分析窗口为 2026-07-29 至 2026-08-11，实际只有 8 份 AI HOT 与 9 份 Builders Digest，不能把缺档日期误写成没有新闻。所有数字都来自底稿，不做装饰性假数据。观点与工具卡必须区分“官方核验”和“仅由本地日报收录”，不能把后者写成已亲测事实。

视觉气质应像一份有编辑判断的“研究备忘录”或“战情简报”：克制、密集但不拥挤、强调阅读节奏与证据层级。避免紫蓝渐变、通用科技霓虹、bento 卡片墙、标题前 emoji、每段配无意义图标、圆角卡片加左彩色边框。可以使用温暖纸色、深墨、砖红或克制的冷蓝作为单一 accent；display 字体优先中文衬线或 Georgia/宋体组合，正文用微软雅黑/思源黑体类易读字体。页面主宽度约 1180px，正文最小 16px，中文行高 1.75 左右。移动端需要自然变为单栏，目录不遮挡内容，可点击目标至少 44px。

页面不需要图片：这是工具、数据和观点型内容，图片不是信息必需。允许使用纯 CSS 的细网格、编号、大字排版、真实数据条形图或矩阵，但不能使用装饰性 SVG 场景。可以有 sticky 目录、主题筛选、选题详情折叠、打印按钮和“只看 A 级工具/只看优先选题”的轻交互；所有交互必须在 `file://` 下工作，不依赖框架、CDN、外部字体或后端。链接可以指向本地日报相对路径和官方网页。

三种设计变体需共享完全相同的真实内容，只探索视觉与信息组织：

1. **编辑部研究简报**：暖纸底、黑墨排版、砖红重点、强编号和窄栏注释，像杂志长文与研究备忘录结合。
2. **工程作战手册**：浅灰蓝底、深蓝与荧光黄少量点题、等宽标签、流程与验证感强，像一份可执行 runbook，但不能做成通用 GitHub-dark。
3. **信号地图**：高对比黑白、单一橙色，利用纵向时间轴、连线和优先级矩阵表现“信号 → 判断 → 行动 → 选题”，更大胆但仍保证长文可读。

最终 HTML 必须在开头保留注释，写清目标受众、内容假设、事实边界与图片决策。文件名分别为 `editorial-brief.html`、`operations-manual.html`、`signal-map.html`，保存在 `design-demos/`。每版都要完整包含九个观点、工具清单和十个选题，不能只做一屏概念稿。交付前需检查 console error、桌面 1440×900 与移动 390×844 两个视口、页面内锚点、筛选或折叠交互，以及打印样式。
